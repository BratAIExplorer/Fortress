Session 32 — BETA Welcome Modal (signed-in users, every login)

NOT YET DEPLOYED New: components/fortress/WelcomeBetaModal.tsx

A one-time-per-session popup (distinct from the existing persistent BetaBanner.tsx) shown to every signed-in user, reminding them the product is in public BETA and inviting feedback. Built at the user's request after iterating on copy and visual style.

  • Fires once per browser session (sessionStorage key fortress-welcome-modal-seen) — reappears on the next login, unlike the banner's permanent localStorage dismiss.
  • Generic copy — deliberately does not name specific tabs/features, since not everything is enabled for everyone yet.
  • Explicit "Not financial advice" disclaimer block — informational only, user's own responsibility to research before acting.
  • Close (X) button and a primary "Let's go" button — both dismiss for the current session only.
  • "Got feedback?" button opens the existing FeedbackModal.tsx — no new backend, reuses POST /api/feedback.
  • Visual style: dark card, amber/orange accents, scrolling stock-ticker marquee strip, floating coin/trend icons, rotated "PUBLIC BETA" corner ribbon — matched to a poster-style reference image the user supplied.
  • Wired into app/layout.tsx globally, rendered alongside BetaBanner.

Originally scoped to only show during each user's first 30 days (via authUser.createdAt, same pattern as Momentum Radar's trial gate — this required a temporary addition to /api/auth/session to expose createdAt). The user asked to drop that entirely for the BETA phase — every signed-in user sees it, no expiry — so the createdAt plumbing was reverted out of session/route.ts to avoid unused code. A ponytail: comment marks the spot in WelcomeBetaModal.tsx to add real gating (e.g. subscription-based) once out of BETA.

Not yet committed or deployed. Not visually verified in a live browser this session — the Browser pane wasn't compositing frames in this environment; verification was limited to tsc --noEmit (clean) and dev-server logs (no runtime errors on the touched routes).

Most Recent Session — Auth Breakage & Momentum Radar Gate Removed

KNOWN ISSUE Password reset is broken in production.

Root cause: SMTP is not configured on the VPS (SMTP_HOST/SMTP_USER/SMTP_PASSWORD). /api/auth/forgot-password deliberately swallows the email-send failure and always returns success (this is correct behavior — it avoids leaking which emails are registered) — but it means no reset email ever actually arrives, with no visible error anywhere. This has been a known backlog item since Session 28 and was never completed.

This surfaced because a user (arundsamant@gmail.com) couldn't reset their password. That exact email does not appear to match any row in auth_user — needs a manual DB check (see Backlog).

WORKAROUND SHIPPED POST /api/admin/generate-reset-link

Admin-only endpoint (shared x-cron-secret auth, same pattern as the scan crons) that mints a valid PASSWORD_RESET token directly and returns the reset URL — bypassing email entirely. Use it to manually unblock a user until SMTP is fixed:

curl -X POST https://fortressintelligence.space/api/admin/generate-reset-link \
  -H "Content-Type: application/json" \
  -H "x-cron-secret: <CRON_SECRET from /opt/fortress/.env.production>" \
  -d '{"email":"user@example.com"}'

Commit: ad2b3b6b. Retire this once SMTP is fixed and forgot-password is verified end-to-end.

TEMPORARY CHANGE Momentum Radar: sign-in/trial gate removed

Because auth is currently unreliable (see above), gating a feature behind broken sign-in blocked everyone. Decision: open the tab to all visitors (logged in or not) with live MACD signal data, and defer re-gating until auth/SMTP is solid.

  • components/fortress/Navbar.tsx — Momentum Radar link no longer conditional on isLoggedIn.
  • app/api/analysis/momentum-signals/route.ts — GET no longer calls requireAuth or checks the 30-day trial window; just returns the signals table.
  • app/momentum-radar/page.tsx — dropped the unauthenticated/trial_expired UI states; always fetches and renders.

Commit: d8209c46. The original gated version (session/trial check) is intact in git history — restore it once auth is fixed rather than rewriting from scratch.
